DAY 01Foundations

Automation basics

Goal: Automation basics — understand the core concepts and explain them in your own words.

Learn

Automation is software doing a task automatically after an event, schedule, or rule. A process is the work sequence; a workflow is connected steps; a trigger starts it; an action does work; input is received data; output is produced data; an execution is one run.

Worked example

New enquiry → check required fields → save lead → notify staff.

Practice

Draw a process you know. Label its trigger, inputs, actions, output, and one possible failure.

Show self-check answer

Automation uses software to perform steps automatically. AI is optional.

DAY 02Foundations

Finding useful tasks

Goal: Finding useful tasks — understand the core concepts and explain them in your own words.

Learn

Good candidates are frequent, repetitive, rule-clear, valuable, and low-risk. Value may mean time saved, fewer errors, faster responses, or better visibility. An exception is a case outside the normal path. Human-in-the-loop means a person reviews or approves an important step.

Worked example

A notification for every new form is a safer first project than automatically approving refunds.

Practice

List three repetitive tasks. Score each for frequency, clarity, value, and risk. Choose one small candidate.

Show self-check answer

Choose a repeatable task with clear rules, useful benefits, and manageable risk.

DAY 03Workflow logic

Process mapping

Goal: Process mapping — understand the core concepts and explain them in your own words.

Learn

A process map shows steps, decisions, owners, and results. A dependency means one step needs another step's output. A decision point creates different paths. Acceptance criteria define what success looks like.

Worked example

Form arrives → validate → [valid?] yes: save; no: send to review.

Practice

Map an enquiry workflow. Include missing contact details, duplicate submissions, and notification failure.

Show self-check answer

Every step should have a clear purpose, input, output, and next step.

DAY 04Workflow logic

Conditions and branching

Goal: Conditions and branching — understand the core concepts and explain them in your own words.

Learn

A condition evaluates true or false. IF/ELSE chooses paths. AND means every condition must be true; OR means at least one must be true; NOT reverses a condition. A filter allows only matching records to continue. Validation checks data against rules.

Worked example

IF email exists AND consent is true → prepare a reply; ELSE → flag for review.

Practice

Write rules for missing email, order above 5000, urgent support, and new vs returning customer.

Show self-check answer

AND requires all conditions; OR requires at least one. Test both passing and failing examples.

DAY 05Data essentials

Data and records

Goal: Data and records — understand the core concepts and explain them in your own words.

Learn

A record describes one entity. A field is an attribute, such as email. A string is text; a number supports numeric operations; a Boolean is true/false. Null, a missing field, and an empty string differ. Arrays are ordered lists. A unique identifier distinguishes records. Normalization makes formats consistent.

Worked example

1500 is a number; "1500" is text. Extra spaces can make values inconsistent.

Practice

Create five fictional leads including duplicate, missing email, extra spaces, and budget stored as text. Decide how to handle each.

Show self-check answer

Inspect actual values; normalize deliberately and never invent missing customer details.

DAY 06Data essentials

JSON essentials

Goal: JSON essentials — understand the core concepts and explain them in your own words.

Learn

JSON is a text format for structured data, not a programming language. Objects use curly braces; arrays use square brackets; keys and strings use double quotes. Values may be strings, numbers, Booleans, null, arrays, or objects. Array indexes start at zero. JSON has no comments or trailing commas.

Worked example

{
  "name": "Sam",
  "budget": 1500,
  "needsReply": true,
  "services": ["Automation", "Website"],
  "address": {"city": "Delhi"},
  "assignedTo": null
}

Practice

Change budget to 2500, add a service, change city, set needsReply to false, and explain assignedTo.

Show self-check answer

Objects use braces, arrays use brackets, strings use double quotes, and Boolean/null values are unquoted.

DAY 07Tool concepts

Automation platforms and n8n

Goal: Automation platforms and n8n — understand the core concepts and explain them in your own words.

Learn

An automation platform connects services and coordinates steps. In n8n, a node is one step; the canvas is the editor; a connection passes control/data; parameters configure a node; credentials store authentication; an execution is one run; pinned data is saved sample output and may be stale.

Worked example

Manual Trigger → Edit Fields → inspect the output.

Practice

Draw a three-node workflow and annotate each node's input, action, and output.

Show self-check answer

No. Check node configuration and inspect actual input and output data.

DAY 08Tool concepts

Triggers and webhooks

Goal: Triggers and webhooks — understand the core concepts and explain them in your own words.

Learn

A manual trigger starts a test run when you choose. A schedule trigger runs at configured times. An app trigger responds to a supported event. A webhook receives an incoming HTTP request. Polling repeatedly checks for updates. A payload is the data sent with an event. Test and production webhook URLs may behave differently.

Worked example

Daily reminder → schedule trigger. New form submission → event trigger or webhook.

Practice

Choose a trigger for daily reminders, form submissions, and a monthly report. Explain why.

Show self-check answer

A webhook receives an incoming request; an HTTP Request node sends a request to another service.

DAY 09Integrations

APIs and HTTP

Goal: APIs and HTTP — understand the core concepts and explain them in your own words.

Learn

An API is a defined interface for software communication. An endpoint is a URL for a resource or operation. HTTP methods include GET, POST, PATCH, and DELETE; exact behaviour depends on the API. Headers carry metadata/authentication; query parameters are in the URL; a body contains submitted data. Status codes describe the response. Pagination retrieves multiple pages; rate limits restrict request frequency; timeouts limit waiting.

Worked example

Common codes: 200 success, 201 created, 400 bad request, 401 unauthenticated, 403 forbidden, 404 not found, 429 rate limited, 500 server error.

Practice

Label the method, endpoint, headers, body, and expected response in a fictional request. Explain 401, 404, and 429.

Show self-check answer

Identify method, URL, parameters, headers, body, authentication, status, and response body.

DAY 10Data flow

Expressions and mapping

Goal: Expressions and mapping — understand the core concepts and explain them in your own words.

Learn

Field mapping connects a source field to a destination field. A fixed value stays the same; an expression reads or calculates a dynamic value. Data shape means the real structure of incoming data. An item is one unit of data; workflows can pass multiple items. Nested fields sit inside objects.

Worked example

In n8n, `{{ $json.email }}` reads email from the current item; `{{ $json.address.city }}` reads a nested city if that path exists.

Practice

Given a fictional object, identify how to access name, email, and address.city. Explain why `$json.body.email` works only when email is inside body.

Show self-check answer

Inspect the previous node's actual output and match the field path exactly.

DAY 11Security

Credentials and safety

Goal: Credentials and safety — understand the core concepts and explain them in your own words.

Learn

An API key or token can grant access. OAuth lets an app receive authorized access without directly sharing the user's password. Scopes define permissions. Least privilege means granting only necessary access. Keep secrets out of public notes, source code, screenshots, and logs. Use fictional or sanitized test data.

Worked example

Use a dedicated test account and only the permissions needed for the workflow.

Practice

Make a security checklist for an enquiry workflow. Identify necessary data, who can access it, and how to revoke access.

Show self-check answer

Anyone who obtains the key may misuse its permissions. Store secrets securely and revoke/rotate exposed keys.

DAY 12Reliability

Debugging and reliability

Goal: Debugging and reliability — understand the core concepts and explain them in your own words.

Learn

Debugging finds where actual behaviour first differs from expected behaviour. Inspect node input, settings, and output. A retry runs an operation again; backoff waits longer between attempts. Idempotency prevents repeated requests from causing unintended duplicate effects. Logs and alerts help detect failures. A timeout does not prove the remote action failed.

Worked example

A message request times out; blindly retrying may send the message twice if the first request succeeded.

Practice

Plan responses for missing email, invalid data, duplicate form, API 429, and notification timeout.

Show self-check answer

A remote action may have succeeded even if the response was lost. Verify state or use an idempotent design.

DAY 13Advanced foundations

JavaScript essentials

Goal: JavaScript essentials — understand the core concepts and explain them in your own words.

Learn

A variable names a value. `const` prevents reassignment of the binding; `let` allows reassignment. Objects group properties; arrays store lists. Conditions choose behaviour. Functions accept inputs and can return results. `map()` transforms array elements; `filter()` keeps matching elements. n8n Code nodes also have platform-specific input/output conventions.

Worked example

const lead = { name: "Sam", budget: 1500 };
const greeting = "Hello " + lead.name;
function addTax(amount) { return amount * 1.18; }

Practice

Explain each line and predict addTax(100). You do not need to master JavaScript before your first workflow.

Show self-check answer

A variable names a value, an object groups properties, and a function can return a result from its input.

DAY 14AI foundations

AI and agents

Goal: AI and agents — understand the core concepts and explain them in your own words.

Learn

Rule-based automation follows explicit rules. AI models generate or interpret content and can be wrong. A prompt gives instructions and context. Structured output constrains format but does not guarantee truth. Hallucination means plausible but incorrect output. An AI agent may choose steps or tools toward a goal. Evaluation tests output against criteria; human approval adds a review before important actions.

Worked example

Enquiry → validate → AI drafts reply from supplied facts → human approves → send.

Practice

Write a prompt that forbids inventing prices or deadlines and asks the model to flag missing information. List three checks before sending.

Show self-check answer

Start with drafts and human approval. Test accuracy, privacy, costs, and failure cases.

DAY 15Practical readiness

Project design and readiness

Goal: Project design and readiness — understand the core concepts and explain them in your own words.

Learn

Scope defines what a project will and will not do. A test case specifies input and expected result. The happy path is the normal case; edge cases cover unusual conditions. Observability uses logs/status/alerts to understand behaviour. Maintenance keeps integrations working as services change. Measure actual results; never invent performance claims.

Worked example

Manual/Form Trigger → validate → check duplicates → save lead → draft reply → human approval → test notification → log result.

Practice

Write your business problem, workflow steps, inputs/outputs, five test cases, safeguards, and success measures. Start with fictional data on your laptop.

Show self-check answer

If not, identify the specific concept to revisit. You can begin practical work without mastering every advanced topic.
